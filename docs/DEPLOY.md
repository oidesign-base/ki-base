# Розгортання панелі на хостингу

## Як влаштовано

| Локально (`D:\ki-base`) | На сервері (`/home/alexivan/panel`) | Що це |
|---|---|---|
| `app/` | `app/` | Код, шаблони сторінок, конфіг, сховище. Поза вебом |
| `public/` | `public/` | Корінь піддомена `panel.kistudio.pro`: `index.php`, `.htaccess`, статика |
| `db/`, `docs/`, `deploy/`, `LOG.md`, `CLAUDE.md` | — | Лише локально й у git |

Заливка — `deploy\deploy.bat` (WinSCP, FTP з TLS). Спершу показує, що зміниться на сервері, і питає підтвердження. Передаються лише змінені файли.

**Ніколи не заливаються й ніколи не видаляються на сервері:**
- `app/config/config.local.php` — конфіг сервера з паролями;
- `app/storage/` — логи, сесії, фото, бекапи.

Файли, видалені локально з `app/` чи `public/`, видаляються і на сервері.

## Перше розгортання

### 1. Окремий користувач бази для панелі

cPanel → **Бази даних MySQL**:
1. «Додати нового користувача»: наприклад `alexivan_kbapp`, надійний пароль → зберегти в менеджері паролів.
2. «Додати користувача до бази»: `alexivan_kbapp` → `alexivan_ki_base`.
3. Права — **лише**: `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `LOCK TABLES`, `SHOW VIEW`.
   Панелі не потрібні права змінювати структуру бази: міграції застосовуються вручну через phpMyAdmin. Останні два права знадобляться для нічного бекапу.

### 2. Ключ застосунку

У Git Bash:

```bash
openssl rand -base64 32
```

Отриманий рядок — у менеджер паролів. Ним шифруватимуться токени Etsy, OneDrive тощо; без нього їх не прочитати.

### 3. Перша заливка

1. Переконатися, що в WinSCP збережене підключення називається саме **`ki-base`** (так його відкриває скрипт).
2. Запустити `deploy\deploy.bat` подвійним кліком.
3. Переглянути список змін → `Y`.

Після цього `https://panel.kistudio.pro` показуватиме «Панель не налаштована» — це очікувано до наступного кроку.

### 4. Конфіг на сервері

cPanel → **Диспетчер файлів** → `/home/alexivan/panel/app/config/`.

Створити файл `config.local.php` з таким вмістом, підставивши свої значення:

```php
<?php
return [
    'db' => [
        'host'     => 'localhost',
        'name'     => 'alexivan_ki_base',
        'user'     => 'alexivan_kbapp',
        'password' => 'ПАРОЛЬ_КОРИСТУВАЧА_БАЗИ',
    ],
    'security' => [
        'app_key' => 'КЛЮЧ_З_КРОКУ_2',
    ],
];
```

Файл створюється одразу на сервері й локально не зберігається — так паролі не лежать у теці проєкту. Поки файла немає, панель показує «Панель не налаштована» (код 503).

### 5. Створення користувачів

Відкрити `https://panel.kistudio.pro` → панель сама перейде на сторінку налаштування → створити одного або двох користувачів. Після цього сторінка налаштування зникає (404).

## Наступні оновлення

Лише `deploy\deploy.bat`. Якщо змінюється структура бази — у `db/migrations/` з'являється новий файл, і його треба імпортувати через phpMyAdmin **до** заливки коду.

## Якщо щось пішло не так

- **«Помилка сервера» (500)** — подробиці у `/home/alexivan/panel/app/storage/logs/app-РРРР-ММ-ДД.log`.
- **«Панель не налаштована» (503)** — немає `app/config/config.local.php` або в ньому не заповнені дані бази.
- **Журнал останньої заливки** — `deploy\last-deploy.log` (локально, не в git).
